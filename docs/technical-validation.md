# Technical validation gate

Run the reproducible gate from a clean checkout:

```powershell
$env:KEELMATRIX_NO_TELEMETRY = '1'
pwsh -NoProfile -File scripts/technical-validation-gate.ps1 -OutputPath artifacts/technical-validation-gate.md
```

The command restores and builds the solution, runs the complete deterministic corpus, reruns the additive-feed integration test, probes every pinned repository/candidate in `scripts/technical-validation-corpus.json`, and writes Markdown, JSON, an unlabeled blind-judge pack, an independent assessment, and a separate retained ground-truth key under `artifacts/`. It returns `0` only when every mandatory probe and computed go-gate condition passes. It returns `2` when an environment prerequisite is unavailable; the generated records identify each unavailable or skipped probe. A genuine restore, build, test, feed, corpus, blind-assessment, or cleanup failure remains nonzero and is never recorded as a pass.

The gate restores from the checked-in `NuGet.config`, runs the complete deterministic corpus, records SDK/runtime and restore/build/test elapsed time, and writes the Markdown/JSON evidence pair. The corpus covers equivalent stable states, planted package and SDK/runtime breakages, stable fail-A/fail-B, candidate fail-A/fail-B, flaky attempts, `pass → pass → fail → fail`, `pass → fail → pass`, missing preview `UNSUPPORTED`, report determinism, redaction, non-mutation, and cleanup. Runtime-preview probes pass the manifest's `runtimeVersion` (for example, `11.0.0-preview.7.26381.103`) to the candidate-only runtime framework override; they do not rewrite `global.json` or select the preview SDK. The real corpus includes the small MockHttp library, the larger WireMock.Net integration library, Verify’s multi-package testing ecosystem, and three KeelMatrix repositories, all at full commit pins.

The acceptance calculation is computed from `scripts/technical-validation-ground-truth.json` and the observed test results: the detected planted-breakage count and rate must meet the required 95% threshold, and equivalent-state cases must produce zero `FUTURE_REGRESSION` results. The generated key records the expected mapping and observed outcomes separately from the unlabeled samples, so an independent reviewer can recompute the bounded result after the blind pass. Any disagreement is `INCONCLUSIVE_FLAKY`; a missing installed preview is `UNSUPPORTED`; neither can produce a clean exit code.

When a preview SDK/runtime and external repositories are available, pass all exact SDK candidates and checked-out paths with repeated `-PreviewCandidate` and `-RealRepositoryPath` arguments. The script maps each SDK candidate to its exact runtime candidate from `scripts/technical-validation-corpus.json`, verifies both are installed, copies each source into isolated temporary state, and never writes to the source paths. Public CI provisions both real prerelease SDK/runtime candidates and the complete pinned corpus, then uploads the generated artifacts. The local command intentionally remains runnable without those optional inputs and records their absence explicitly rather than claiming those probes ran. `scripts/assess-blind-judge.ps1` independently checks repository identity/revision, control and candidate configuration, exact runtime identity, stable/candidate attempt evidence, reproduction command/configuration, focused-failure placeholder, and normalized signature for every unlabeled witness; this evidence is not a release authorization.
